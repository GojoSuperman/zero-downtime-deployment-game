1. 오늘 배운 핵심 개념

🏥 고가용성 (High Availability)

가용성 = 서비스를 쓸 수 있었던 시간의 비율 → 9의 개수로 표현

  • 고가용성의 3단계: 이중화 → 장애 감지 → 장애 조치
  • SPOF(단일 장애점): 하나만 고장 나도 전체가 멈추는 곳 → 이중화로 해결
  • 무상태(stateless): 서버가 요청 사이에 데이터를 자기 안에 두지 않는 것

🔄 무중단 배포 3가지 방식

롤링

서버를 한 대씩 돌아가며 교체

+ 추가 서버 불필요 - 신/구 혼재

블루그린

서버 두 벌 준비, 방향을 한 번에 전환

+ 깔끔한 전환, 빠른 롤백 - 서버 2배 필요

카나리

새 버전에 1~10%만 먼저 보내기

+ 위험 최소화 - 느리고 모니터링 필요

배포 시 지켜야 할 3가지: 헬스체크 그레이스풀 셧다운 DB 호환성

⚖️ 로드밸런서와 Nginx

로드밸런서 = 요청을 뒤의 서버 중 하나에 넘기는 장치

분배 규칙: 라운드 로빈 최소 연결 가중치 IP 해시

nginx/default.conf
# 뒷단 서버 그룹 upstream app { zone app 64k; server blue:8080; # ← 한 줄만 바꾸면 전환! # server green:8080; } server { listen 80; location / { proxy_pass http://app; proxy_connect_timeout 2s; # 장애 시 빠른 감지 } }

nginx -t 문법 검사 → nginx -s reload 끊김 없이 적용

2. 추가 과제 시도 기록

📋 과제 1: Docker Compose로 통합

blue, green, bg-nginx, 네트워크를 compose.yaml 하나에 적고 docker compose up 한 번으로 띄우기

compose.yaml
services: blue: image: friend-agent:local environment: [LLM_PROVIDER=fake, K_REVISION=blue, BANNER=BLUE] green: image: friend-agent:local environment: [LLM_PROVIDER=fake, K_REVISION=green, BANNER=GREEN] bg-nginx: image: nginx:1.27-alpine ports: ["8080:80"] volumes: [./nginx:/etc/nginx/conf.d] depends_on: [blue, green] networks: bg-lab: driver: bridge

✅ 검증 docker compose down && up -d 반복 시 동일 구성 재현

📋 과제 2: 롤링 배포 (Nginx)

컨테이너 3개를 upstream에 두고, 한 대씩 down → 교체 → 복귀를 반복

✅ 검증 이전/새 버전이 섞여 찍히다가 새 버전만 남음, 실패 0건

📋 과제 3: 능동 헬스체크 스크립트

2초마다 green의 /health를 확인하고 2회 연속 실패 시 upstream에서 제거 + reload

✅ 검증 docker stop green 후 자동 감지 및 제거 확인

📦 GCE 구축 순서

STEP 1
프로젝트 생성
gcloud projects create bluegreen-lab-2026 → 결제 연결 → Compute Engine API 활성화
STEP 2
VM 생성
gcloud compute instances create (e2-medium, Ubuntu, 20GB) + 방화벽 TCP 8080
STEP 3
Docker 환경 구축
SSH 접속 → Docker 설치 → friend-agent 클론 + 이미지 빌드
STEP 4
서비스 시작
docker compose up -d → 외부 브라우저에서 BLUE 배너 확인 ✅
STEP 5
블루그린 전환 성공
sed + nginx -s reload → GREEN 전환 확인 ✅
STEP 6
비용 관리
gcloud compute instances stop으로 일시정지 (과금 중지)

💰 VM 비용 관리 명령

gcloud CLI
# 일시정지 (과금 중지) $ gcloud compute instances stop bluegreen-vm --zone=asia-northeast3-a # 다시 시작 $ gcloud compute instances start bluegreen-vm --zone=asia-northeast3-a # 완전 삭제 $ gcloud compute instances delete bluegreen-vm --zone=asia-northeast3-a
